# StudyMate 최종 프로젝트 결과보고서

인공지능 응용 시스템 개발 종합 프로젝트 · 작성일 2026-11-24 · 작성자 반재영 (개인 프로젝트)

> 이 문서의 모든 수치는 `evidence/` 폴더의 평가 원자료와 `node tools/eval.mjs`, `npm test`로 다시 측정할 수 있습니다. 평가 질문과 학습 자료는 개발자가 직접 작성했으므로 실제 학습자 질문에 대한 성능을 보장하지 않습니다(6장 참고).

## 2. 개발 배경

학습자는 자료가 흩어져 있어 설명을 찾기 어렵고, 공부한 뒤에도 어떤 개념이 약한지 알기 어렵습니다. 일반 챗봇은 수업 자료와 다른 설명을 하거나 없는 내용을 지어내는 환각이 있어 학습에 그대로 쓰기 어렵습니다. 그래서 (1) 내 자료를 근거로 출처와 함께 답하고, (2) 근거가 없으면 지어내지 않고, (3) 퀴즈로 이해도를 측정해 (4) 복습 순서까지 제안하는 시스템을 만들었습니다.

### 3.2 시스템 구조
기획서 4장의 구조와 같습니다. 질문은 개인정보를 마스킹한 뒤 BM25로 검색하고, 신뢰도가 임계값(0.3) 미만이면 LLM을 호출하지 않고 거절합니다. LLM이 있으면 상위 3개 항목만 근거로 답하게 하고 숫자·인용·자료 일치도를 검사해, 통과하면 AI 답변으로, 실패하면 자료 원문 발췌로 대체합니다. LLM이 "근거 부족"이라고 답하면 원문을 내밀지 않고 거절합니다.

## 5. 평가

평가 도구: `node tools/eval.mjs` (질문 세트 `evidence/eval-questions.json`). 측정일 2026-11-24, 자료 6개 단원 44개 항목.

### 5.1 검색 정확도 (BM25, LLM 없음)
| 질문 세트 | 문항 | hit@1 | hit@4 |
|---|---|---|---|
| 일반 질문 | 60 | 100.0% (60/60) | 100.0% (60/60) |
| 어려운 질문(자료 표현을 피해 돌려 말함) | 12 | 83.3% (10/12) | 100.0% (12/12) |

일반 질문은 자료의 용어가 질문에 들어 있어 쉬운 편입니다. 어려운 질문에서 틀린 2건은 "시험 문제를 통째로 외워서…"(과대적합)와 "훈련용이랑 평가용 데이터를 섞으면…"(데이터 누수)로, 자료의 용어(과대적합, 학습 데이터/테스트 데이터)를 쓰지 않아 어휘 검색이 놓쳤습니다. 이 한계는 임베딩 검색으로 보완할 수 있지만, 이 PC에서는 임베딩 모델이 비정상 종료되어 검증하지 못했습니다(선택 기능 `EMBEDDINGS=on`).

### 5.2 범위 밖 질문 거절과 임계값
검색 신뢰도 임계값별 효과(범위 안 일반 질문 60개, 어려운 질문 12개, 범위 밖 질문 20개):

| 임계값 | 일반 질문 응답 | 어려운 질문 응답 | 범위 밖 거절 |
|---|---|---|---|
| 0.15 | 100.0% | 100.0% | 55.0% |
| 0.20 | 100.0% | 91.7% | 65.0% |
| 0.25 | 100.0% | 83.3% | 65.0% |
| **0.30 (채택)** | **100.0%** | **83.3%** | **85.0%** |
| 0.40 | 96.7% | 66.7% | 90.0% |

0.2에서 0.3으로 올리면 범위 안 질문 응답을 잃지 않고 범위 밖 거절이 65%에서 85%로 올라 0.3을 채택했습니다. 단, **임계값을 이 평가 세트로 골랐기 때문에 같은 세트의 수치는 낙관적**입니다. 검색 단계만으로는 "주식 투자" 같은 흔한 단어가 겹치는 질문을 완전히 거르지 못해, LLM의 "근거 부족" 응답이 두 번째 방어선이 됩니다.

### 5.3 실제 LLM 답변 (로컬 Ollama kanana2:3b)
일반 질문 60개와 범위 밖 질문 20개를 실제 로컬 LLM으로 `chat.ask` 전체 파이프라인에 통과시켰습니다(원자료 `evidence/eval-llm.json`).

| 지표 | 결과 |
|---|---|
| AI 답변(근거 검사 통과) | 55 / 60 |
| 근거 검사 실패로 원문 발췌 대체 | 5 / 60 (pip·불균형 데이터·활성화 함수·어텐션·404 질문 등, 사유 `ungrounded`) |
| 일반 질문을 거절한 경우 | 0 / 60 |
| 답변 근거에 정답 항목 포함 | 100.0% (60/60) |
| 응답 시간 | 중앙값 2.55초(2,550ms), p90 5.274초(5,274ms) |
| 범위 밖 질문 거절 | **85.0% (17/20)** |

**실패 사례**: 범위 밖 질문 3개("BTS 최신 앨범 뭐야?", "축구 규칙 설명해줘", "카페 창업 비용")는 검색 신뢰도가 0.33~0.70으로 임계값(0.3)을 넘고 LLM 답변이 근거 검사에서 탈락해, 거절되지 않고 **관련 없는 자료 원문이 답으로 나갔습니다**. 같은 신뢰도 범위(0.34)에 정상 질문("404 에러는 무슨 뜻이야?")이 있어 임계값만으로는 구분할 수 없었고, 더 큰 모델이나 문장 단위 근거 검증이 필요합니다(미해결). 정답 문서가 인용된 비율 100%는 "답이 맞다"가 아니라 "정답 항목을 근거로 보여 줬다"는 뜻이며, 답변 문장의 정확성은 사람이 전수 검토하지 않았습니다(일부 확인만).

참고: LLM이 "근거 부족"이라고 답했는데 원문을 내밀던 코드를 거절로 고친 뒤 재측정했으나 수치는 같았습니다(고치기 전 17/20, 원자료 `evidence/eval-llm-before-abstain-fix.json`). 위 3건은 "근거 부족" 선언이 아니라 근거 검사 탈락이 원인이었습니다.

### 5.4 퀴즈 구조 품질 (규칙 기반 출제, 자동 검사)
모든 44개 항목에서 3유형(객관식·빈칸·O/X)을 만들어 **132문제**를 검사했습니다.

| 검사 | 결과 |
|---|---|
| 문제 생성 실패 항목 | 0 |
| 정답이 문제 본문에 노출 | 0 |
| 객관식 보기에 정답 누락 | 0 |
| 보기 중복 | 0 |

이 검사는 **구조**만 봅니다. 문제가 교육적으로 좋은지(오답 보기의 질, 난이도)나 O/X의 "틀린 설명"이 어색하지 않은지는 사람이 평가하지 않았습니다. 알려진 어색함: 용어를 바꿔 만든 O/X에서 조사(은/는, 이/가)가 맞지 않는 경우가 있습니다.

## 6. 한계

1. **자체 작성 자료·질문**: 같은 사람이 자료와 평가 질문을 썼고, 임계값도 같은 세트로 골랐습니다. 실제 학습자의 표현에서는 수치가 낮아질 수 있습니다.
2. **기본 자료는 요약본**: 실제 수업 교재가 아니며, PDF 업로드는 지원하지 않습니다(텍스트로 붙여 넣기).
3. **Claude·ChatGPT 실호출 미검증**: 개발 환경에 API 키가 없어 요청·응답 형식을 가짜 서버로만 검증했습니다. 실제 모델의 모델 ID, 응답 형식, AI 출제 품질은 키를 넣어 확인해야 합니다.
4. **어휘 검색의 한계**: 자료의 용어를 쓰지 않고 돌려 말한 질문은 놓칠 수 있습니다(어려운 질문 hit@1 83.3%). 임베딩 혼합은 미검증입니다.
5. **소형 LLM**: 3B 모델은 조건을 빠뜨리거나 부연을 지어낼 수 있고, 의미가 반대인 답변은 근거 검사로 걸러내지 못합니다.
6. **채점**: 주관식은 문자열 비교라 동의어(오버피팅/과대적합)를 오답으로 처리합니다.
7. **인증 없음**: 학습자를 브라우저에 저장된 임의 ID로 구분하므로 ID를 아는 사람은 해당 기록을 볼 수 있습니다(교육용 데모). 부하·동시접속 시험은 하지 않았습니다.
8. **실사용자 검증 없음**: 화면의 학습 기록·만족도는 시연용 데이터(`tools/seed-demo.mjs`)이며 실제 학습 효과를 측정하지 않았습니다.
9. **외부 LLM 사용 시 개인정보**: 질문은 마스킹하지만 마스킹 규칙(전화·이메일·카드·주민번호)에 없는 개인정보는 걸러지지 않습니다. 자료함에 개인정보나 비공개 자료를 올리지 않아야 합니다.

## 7. 개발 중 발견한 문제와 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| 범위 밖 질문 거절이 65% | 임계값 0.2가 '방법' 같은 흔한 글자 일치까지 근거로 인정 | 임계값 평가표로 비교해 0.3 채택(거절 85%, 범위 안 응답 100% 유지) |
| LLM이 "근거 부족"이라 했는데 원문 발췌가 나감 | 검사 실패를 모두 원문 발췌로 대체 | 근거 부족 선언은 거절로 처리(방어적 수정, 평가 수치는 변화 없음) |
| 범위 밖 3건이 관련 없는 원문을 답으로 냄 | 신뢰도가 정상 질문과 겹쳐 임계값으로 구분 불가 | 미해결, 한계로 기록 |
| 추출형 답변에 관련 없는 문장이 섞임 | 두 번째 문서의 문장을 무조건 포함 | 질문과 겹치는 문장만, 두 번째 문서는 첫 문서의 70% 이상일 때만 포함 |
| 로컬 3B 모델로 AI 출제가 매우 느림 | 문제마다 LLM을 순차 호출 | 로컬은 규칙 기반 출제, Claude·ChatGPT 연결 시에만 AI 출제 |
| 화면에 `[object HTMLDivElement]` 출력 | 노드 배열을 `replaceChildren`에 그대로 전달 | 펼쳐서 전달 후 브라우저에서 재확인 |
| 모바일에서 자료함 화면이 가로로 넘침 | 파일 선택 + 버튼 행이 줄바꿈되지 않음 | 줄바꿈 허용, 375px 폭에서 5개 화면 모두 확인 |

## 8. 향후 개선

- 실제 수업 교재(PDF)와 학습자 질문으로 평가 세트 확대, 임계값을 별도 검증 세트로 재선정
- 임베딩 혼합·재순위화 비교, 형태소 분석
- Claude·ChatGPT 실제 환경에서 답변·출제 품질 측정, LLM 채점으로 동의어·서술형 답안 평가
- 학습자 로그인·권한, 데이터 보관 정책
- 개념 간 선수 관계를 이용한 학습 경로 추천

## 9. 실행 방법

npm start            # http://127.0.0.1:5300 (Windows: 시작하기.cmd)
node tools/seed-demo.mjs   # 시연 데이터(선택) → /?learner=demo-learner-01

## 11. 2026-11-26 인수인계 재검증 및 정정

원본 StudyMate.zip의 소스 및 문서를 인수해 자동 테스트 30개를 Node.js 22.16에서 재실행했다(30/30 통과). Node.js 24 이상을 목표 환경으로 유지한다. 도구 파일 5개에 주석을 추가하고 실행 코드는 변경하지 않았다. `npm test` 명령은 Node.js 24에서 파일을 명시적으로 탐색하도록 수정했다.

| 평가 | 11/26 재실행 |
