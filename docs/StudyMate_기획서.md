# StudyMate 프로젝트 기획서

인공지능 응용 시스템 개발 종합 프로젝트 · 작성일 2026-11-24 · 작성자 반재영 (개인 프로젝트)

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | StudyMate — RAG 챗봇 기반 AI 맞춤형 학습 지원 시스템 |
| 한 줄 요약 | 학습자의 수업 자료를 근거로 질문에 답하고, 퀴즈로 이해도를 측정해 약한 개념을 찾아 복습 순서를 추천하는 학습 도우미 |
| 대상 도메인 | 이번 교육과정 내용(파이썬, 데이터 처리, 머신러닝, 딥러닝, LLM·RAG, 웹·DB·IoT) 6개 단원, 44개 학습 항목(직접 작성한 요약 자료) + 학습자가 추가하는 자료 |
| 핵심 AI 기술 | RAG(검색 증강 생성) 챗봇, LLM 연동(Claude · ChatGPT · 로컬 Ollama 중 선택), 환각 방지 검증, 자료 기반 퀴즈 자동 생성, 라이트너 상자 기반 복습 스케줄링 |
| 개발 환경 | Node.js 24+, SQLite(node:sqlite), HTML/CSS/JavaScript. 외부 npm 패키지 없음 |

## 2. 개발 배경과 목적

학습자는 자료가 여러 곳에 흩어져 있어 필요한 설명을 찾는 데 시간을 쓰고, 공부한 뒤에도 "내가 어디를 모르는지" 알기 어렵습니다. 일반 챗봇에게 물으면 빠르지만 수업 자료와 다른 설명을 하거나 근거 없는 내용을 그럴듯하게 지어내는 환각이 있어, 시험·과제 공부에 그대로 믿고 쓰기 어렵습니다.

**목표**
1. 내 학습 자료에 있는 내용은 **출처(근거 항목)와 함께** 정확히 답한다 (RAG).
2. 자료에 근거가 없으면 지어내지 않고 **"근거를 찾지 못했다"고 답한다** (환각 방지).
3. 자료에서 **퀴즈를 자동으로 만들고 채점**하며, 정답을 미리 노출하지 않는다.
4. 풀이 기록으로 **약한 개념을 찾아 복습 순서를 추천**한다 (정답률 + 복습 시점).
5. 학습자가 **자기 자료를 직접 추가**해 같은 기능을 쓸 수 있게 한다.
6. 운영자(교수자)에게는 **질문 많은 단원·단원별 정답률** 지표를 보여 준다.

## 3. 요구사항 분석

### 3.1 사용자와 시나리오
| 사용자 | 하고 싶은 일 |
|---|---|
| 학습자 | 모르는 개념을 질문하고 근거 자료를 확인한다. 단원별 퀴즈를 풀고, 약점 복습 퀴즈로 틀린 개념을 다시 본다. 내 노트를 자료함에 추가한다. |
| 교수자·운영자 | 학습자들이 많이 묻는 단원과 정답률이 낮은 개념을 확인해 수업 자료를 보완한다. |

### 3.2 기능 요구사항
| ID | 기능 | 완료 기준 |
|---|---|---|
| F1 | 자료 기반 Q&A(RAG) | 답변과 함께 근거 항목(단원·제목·원문)을 표시하고, 후속으로 볼 만한 항목 제안 |
| F2 | 근거 부족 처리 | 검색 신뢰도가 임계값 미만이면 답을 지어내지 않고 안내 문구 출력 |
| F3 | 환각 방지 검사 | AI 답변의 숫자·인용 번호·자료 일치도를 검사하고, 실패하면 자료 원문 발췌로 대체 |
| F4 | LLM 선택 | Claude, ChatGPT, 로컬 Ollama 중 키/서버가 있는 것을 자동 선택, 없으면 추출형 답변 |
| F5 | 설명 수준 | "보통/쉽게" 선택에 따라 답변 길이·말투 조절 |
| F6 | 퀴즈 자동 생성 | 객관식·주관식(빈칸)·O/X 3유형, 정답 비노출, 보기에 정답 포함, AI 출제는 자료와 맞는 문제만 채택 |
| F7 | 채점과 해설 | 문제당 1회 채점, 해설에 원문 근거 표시, 중복 제출 방지 |
| F8 | 학습 분석 | 단원별 정답률, 약점 개념, 숙련도(라이트너 1~5 상자) |
| F9 | 복습 추천 | 약점·복습 시점이 지난 개념·미학습 단원 순으로 오늘의 학습 계획 제안, 약점 복습 퀴즈 |
| F10 | 자료함 | 텍스트/.txt/.md 업로드로 자료 추가·삭제(기본 자료는 삭제 불가), 즉시 검색·퀴즈에 반영 |
| F11 | 개인정보 보호 | 질문 속 전화·이메일·카드·주민번호를 저장·LLM 전달 전에 마스킹 |
| F12 | 운영 지표 | 질문 수, 근거 있는 답변 비율, 평균 응답시간, 도움됨 비율, 단원별 질문·정답률 |
| F13 | 카카오톡 챗봇 연동 | 카카오 i 오픈빌더 스킬 서버 형식(`POST /kakao/skill`)으로 같은 RAG 답변·근거 제공, 5초 제한 대응, 사용자 ID 해시 저장 |

### 3.3 비기능 요구사항
- LLM이 없거나 실패해도 동작(추출형 답변, 규칙 기반 퀴즈로 자동 대체).
- API 키는 `.env`/환경변수로만 읽고 코드·로그·응답에 남기지 않음. 외부 LLM에는 마스킹된 질문과 검색된 자료 일부만 전달.
- 입력 길이 제한, 학습자별 요청 속도 제한, 화면 출력은 `textContent`로만 처리해 XSS 방지.
- 모바일 폭에서도 사용 가능한 반응형 화면.

## 4. 시스템 설계

### 4.1 아키텍처

```
학습자/교수자 (브라우저: 챗봇 · 퀴즈 · 학습현황 · 자료함 · 운영 지표)
        │  REST API (JSON)
        ▼
  Node.js 서버
   ├─ ChatService : ① PII 마스킹 → ② Retriever(BM25, 선택: 임베딩) → ③ 신뢰도 판정
   │                → ④ LLM 어댑터(Claude / ChatGPT / Ollama) → ⑤ 환각 방지 검사
   │                → ⑥ 실패 시 추출형 답변, 근거 없으면 거절
   ├─ QuizService : 개념 우선순위 선정 → AI 출제(검증) 또는 규칙 기반 출제 → 채점
   ├─ Learning    : 개념별 숙련도 → 약점·복습 추천
   └─ 자료 관리   : knowledge/*.md + data/materials/*.md 로드, 업로드 청크 분할
        ▼
  SQLite: learners · qa_log · quiz_items · attempts · mastery
```

### 4.2 RAG 파이프라인
1. **색인**: 자료를 `## [ID] 제목` 항목 단위로 분할하고 문자 바이그램 토큰으로 BM25 색인(형태소 분석기 없이 한국어 조사 변화에 대응).
2. **검색**: 질문에서 군말을 제거하고 상위 4개 항목을 선택, 질문 토큰 커버리지와 자료에 없는 단어 비율로 **신뢰도** 계산.
3. **분기**: 신뢰도 임계값 미만이면 답하지 않고 안내(자료 추가 유도).
4. **생성**: 상위 3개 항목만 프롬프트에 넣고 "자료에 없으면 '근거 부족'이라고만 답하라"고 지시. 자료·학습자 메시지 안의 지시문은 따르지 않도록 명시.
5. **검증**: (a) 답변 숫자가 자료·질문에 있는지, (b) 인용 번호 범위, (c) 답변 바이그램의 자료 일치도 ≥ 0.5. 실패 시 질문과 겹치는 원문 문장만 발췌해 답변.

### 4.3 퀴즈 생성과 학습 분석
- 자료의 **굵은 글씨(`**용어**`)** 를 핵심 용어로 사용(없으면 드문 단어를 자동 선정).
- 규칙 기반: 문장에서 용어를 가려 **빈칸/객관식**을 만들고, 다른 개념의 용어를 오답 보기로 사용. 용어를 다른 개념의 용어로 바꿔 **O/X** 문제 생성.
- AI 기반(Claude·ChatGPT 연결 시): 항목 본문만 근거로 JSON 문제 생성 → 보기 4개·정답 번호·정답 노출 여부·자료 일치도를 검사해 **통과한 문제만** 채택, 아니면 규칙 기반으로 대체.
- 복습 우선순위 = (1 − 평활 정답률) + 복습 시점 경과 가산 − 숙련 감산, 안 푼 개념은 중간 값. 라이트너 상자(1~5): 정답이면 상자 상승(복습 간격 0·1·3·7·14일), 오답이면 1번으로.

### 4.4 데이터 설계
| 테이블 | 주요 컬럼 |
|---|---|
| learners | id, name |
| qa_log | id, learner_id, question(마스킹됨), answer, generator(llm/extractive/none), confidence, unit, sources, latency_ms, feedback |
| quiz_items | id, learner_id, chunk_id, unit, qtype, generator, prompt, options, answer, explanation, answered |
| attempts | id, learner_id, item_id, chunk_id, unit, qtype, user_answer, correct |
| mastery | (learner_id, chunk_id) PK, box, due_at, attempts, correct, last_at |

### 4.5 API
`POST /api/chat`, `POST /api/chat/:id/feedback`, `POST /api/quiz`, `POST /api/quiz/:id/answer`, `GET /api/progress`, `GET /api/recommend`, `GET/POST/DELETE /api/materials`, `GET /api/units`, `GET /api/kb`, `GET /api/kb/search`, `GET /api/stats`, `GET /api/status`, `POST /kakao/skill`(카카오톡 스킬 서버).

## 6. 평가 계획
- **검색 평가**: 정답 항목이 정해진 질문 60개 + 자료 표현을 피해 돌려 말한 어려운 질문 12개 → hit@1, hit@4, MRR.
- **범위 밖 질문**: 날씨·주식·요리 등 20개 → 거절 비율, 임계값별 효과(범위 안 질문 응답률과의 균형).
- **답변 평가**: 실제 LLM으로 질문 80개를 돌려 AI 답변 통과율·원문 대체율·거절 수·응답 시간을 측정하고 개발자가 수기 검토.
- **퀴즈 품질**: 모든 항목에서 문제 생성 가능 여부, 정답 노출·보기 누락·보기 중복 건수를 자동 검사.
- **단위·통합 테스트**: LLM 어댑터(Claude·ChatGPT 요청 형식, 실패 처리), 환각 방지, 퀴즈·채점·복습 추천, HTTP API를 자동 테스트로 검증.
- 평가 질문과 자료는 개발자가 직접 작성하므로 실제 학습자의 질문 분포와 다를 수 있음을 결과보고서에 명시한다.

## 9. 위험과 대응
| 위험 | 대응 |
|---|---|
| LLM의 환각·불안정한 문장 | 자료 안에서만 답하도록 지시, 숫자·인용·자료 일치도 검사, 실패 시 원문 발췌 또는 거절 |
| AI가 만든 문제의 오류 | 자료와의 일치도·정답 노출 검사를 통과한 문제만 채택, 아니면 규칙 기반 문제로 대체 |
| 한국어 검색 정확도(형태소 분석기 없음) | 문자 바이그램 + 조사 제거, 평가 세트로 측정 후 보완, 선택적으로 임베딩 혼합 |
| 발표 환경의 네트워크·API 키 문제 | LLM 없이도 동작하는 추출형 답변과 규칙 기반 퀴즈, 시연 영상 준비 |
| API 키·개인정보 유출 | 키는 `.env`(git 제외)로만 관리, 질문의 개인정보는 외부 전송 전 마스킹 |
| 외부 API 비용 | 학습자당 질문 속도 제한, 입력 길이 제한, 소형 모델(Claude Haiku·GPT-4o mini급) 기본 사용 |

## 10. 2026-11-26 인수인계 보완

실제 조립 경로의 검색 신뢰도 임계값은 0.3으로 유지한다(클래스 자체 기본값 0.2와 구분). 카카오 오픈빌더 스킬은 응답·시간 제한·토큰 검사를 자동 테스트로 확인하며 실제 채널 연동은 별도 과제이다. SQLite의 관계는 코드 수준 논리 참조이며 FOREIGN KEY·CHECK 제약은 없다. 단위 테스트와 평가 재실행 결과, 문서 목록, 생성 방법은 `docs/README.md` 및 결과보고서 11절에 정리했다.
